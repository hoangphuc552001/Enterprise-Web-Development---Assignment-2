# AI Usage Documentation

## Tool Used

**Claude Code CLI**

---

## Overview

I used AI primarily for tasks that involved integrating AWS infrastructure and errors.
Core application logic, component design, routing structure, and UI decisions were developed independently first, with AI used to accelerate specific implementation steps.

---

## Tasks AI Assisted With

### 1. Planning implementation

With the assignment requirements, I ask AI to help me break down the implementation into discrete tasks and identify which files/modules would be affected by each task.
The implementation_plan will be attached in folder "AI_RESOURCES" for reference.

### 2. UI redesign

I brainstorm the idea of UI components/layout then ask AI to put css classes to the components and give me the code for the redesigned pages.
For React logic such as useState, useEffect, I owned implementing them by myself.

### 3. Debugging

Sometimes when integrating AWS services, I encounter errors that are not straightforward such as version/configuration mismatches or missing IAM permissions.
I ask AI to help me understand the error messages and suggest potential fixes.

### 4. Code explanation + improvements

I copy the code and ask AI what the code does, how it works, and if there are any potential issues or improvements.

### 5. Type-checks, linters, and live tests

## For routine checks such as type-checking, linting, or running live tests, I ask AI to run the commands and report any issues or errors it finds.

## AI Resources

The full AI resources used are stored in the `AI_RESOURCES` folder

---

## Summary

In all cases, I read the generated code or implementation plan then understood and update flow on my own mindset.
For some repeatedly tasks such as type-checks running, linters, live tests, or explaining code I mostly based on AI.
The core application features were written/rewritten by hand and reflect my own understanding.
